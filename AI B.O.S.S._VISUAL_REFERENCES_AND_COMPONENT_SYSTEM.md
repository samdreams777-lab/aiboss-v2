# AI B.O.S.S. V2 — VISUAL REFERENCES & COMPONENT SYSTEM

## 1. PURPOSE

This document defines the visual references, interaction references, design principles, and component-level implementation guidance for AI B.O.S.S. V2.

The references below are **not templates to copy literally**.

They are reference sources for specific:

* visual principles
* interaction patterns
* typography
* composition
* storytelling
* product presentation
* motion
* navigation
* conversion patterns
* responsive behavior

The final AI B.O.S.S. V2 website must combine these principles into a **single coherent visual system**.

# 11. WHAT NOT TO DO

Avoid:

* AI robots
* generic glowing brains
* excessive neon
* random gradients
* meaningless 3D objects
* decorative WebGL
* excessive glassmorphism
* generic SaaS card grids
* giant paragraphs
* template-like dashboards
* animation everywhere
* excessive rounded cards
* visual effects that hide information

The visual sophistication should come from:

* typography
* composition
* motion
* real interfaces
* transitions
* interaction
* information hierarchy

# 24. TYPOGRAPHY

Typography is a major part of the visual identity.

Desired hierarchy:

### Level 1

Very large statement typography.

Used for:

* Hero
* major transformation statements
* Journey
* section transitions

### Level 2

Strong section titles.

### Level 3

Product/module titles.

### Body

Highly readable.

Avoid excessive small text.

On mobile:

Typography must scale intelligently.

Never solve responsive problems by simply shrinking everything.

---

# 25. COLOR

Do not blindly copy the colors of Linear, Stripe, Vercel or any other reference.

Create an AI B.O.S.S. color system.

The palette should support:

* premium appearance
* high contrast
* readability
* clear CTA
* system/module differentiation
* light/dark sections if useful

Color should communicate hierarchy and state, not decoration.

---

# 26. CARDS

Cards should not become the default layout for everything.

Use cards when they represent:

* product modules
* projects
* articles
* selectable business scenarios

Prefer larger editorial/product compositions for major sections.

Avoid:

6–12 identical rounded cards in every section.

---

# 27. ANIMATION SYSTEM

Animation categories:

### MICRO

* button hover
* link hover
* icon transition
* menu state

### COMPONENT

* card reveal
* product preview
* module activation

### SECTION

* before → after
* journey progression
* process transition

### PAGE

* route transition where appropriate

Animation should have a hierarchy.

Not every element should animate independently.

---

# 28. MOTION PERFORMANCE

Prefer:

* transform
* opacity
* CSS
* lightweight JS animation
* SVG

Use GSAP or equivalent when it provides clear value.

Use WebGL / Three.js only when the visual effect genuinely improves the product story.

Every advanced animation must have:

* mobile fallback
* reduced-motion fallback
* acceptable performance

---

# 32. REFERENCE DECISION PROCESS FOR HERMES

When implementing a component:

### STEP 1

Identify the purpose of the component.

### STEP 2

Select the relevant reference.

### STEP 3

Study the reference's interaction principle.

### STEP 4

Adapt that principle to AI B.O.S.S.

### STEP 5

Test desktop.

### STEP 6

Create a deliberate mobile equivalent.

### STEP 7

Test performance.

### STEP 8

Test reduced motion.

### STEP 9

Verify that the component belongs to the overall AI B.O.S.S. visual language.

# 35. FINAL DESIGN TEST

Before accepting any major page, ask:

### QUESTION 1

Does this show what AI B.O.S.S. can actually build?

### QUESTION 2

Does the visitor understand the business benefit quickly?

### QUESTION 3

Does the interaction communicate something meaningful?

### QUESTION 4

Does this look like AI B.O.S.S. rather than another SaaS template?

### QUESTION 5

Would a local business owner think:

> "I want this for my business."

If the answer to the final question is NO, the design is not finished.
